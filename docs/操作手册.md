# 综测平台操作手册

按角色分三部分：**A. 管理员/辅导员**（学期全流程）、**B. 班级负责人（班委）**、**C. 学生**。接口前缀均为 `/api/v1`（前端就绪前可用 curl/Postman 按本手册操作）。

---

## A. 管理员 / 辅导员

账号：超管 `admin`（seed 初始化，首登强制改密）。辅导员账号由超管在「用户管理」创建（角色 GRADE_ADMIN）。

### A1. 建批次（每学期一次）

```
POST /batches                { semesterKey: "2025-2026-1", name: "2025-2026学年第一学期综测" }
POST /batches/:id/activate-rules          # 把当前规则字典快照为本批次口径（改规则不影响进行中批次）
```

批次状态机（只能顺序流转，`POST /batches/:id/transition {to}`）：
`DRAFT → DATA_PREP → COLLECTING → FIRST_REVIEW → SECOND_REVIEW → CALCULATED → PUBLICITY → ARCHIVED`

### A2. 导入学生（1035 人 xlsx）

```
POST /imports/preview?kind=STUDENT   (multipart file)   → { token, headers, mapping, totalRows }
POST /imports/confirm                { token, kind:"STUDENT", mapping }  → { jobId }
GET  /imports/jobs/:id               轮询至 DONE（summary: total/inserted/updated/skipped）
```

- 列名自动映射（学号/姓名/班级/学籍状态…），确认 mapping 后才入库；重复导入按学号更新
- 自动为每个学生建账号：用户名=学号，初始密码=学号后 6 位（可用 `STUDENT_INIT_PWD_MODE=LITERAL:xxx` 改固定串），首登强制改密

### A3. 导入成绩（多学期混合 xls）

同上，`kind=GRADE`，confirm 时传 `batchId + termKey`（如 `2025-2026-1`，preview 会列出文件里出现过的全部学期）。

导入即分类落异常队列（`GET /grades/issues?batchId=&type=&resolution=&page=`，返回 `{items,total,typeCounts}`）：

| 类型 | 含义 | 默认计算行为 | 建议裁决 |
|---|---|---|---|
| RESIT_DUP | 补考多行 | 期末考试行优先；无期末取最高分（AUTO flag） | 有争议时 `PATCH /grades/issues/:id/resolve {resolution:"MANUAL_PICKED", pickedGradeId}` |
| MISSING | 缺考 | scoreValue 置空；必修计扣分 | 确认后 `INCLUDED`；误录 `EXCLUDED` |
| DEFERRED_EMPTY | 缓考无成绩 | 该课剔除 + 学生置 PENDING_DEFERRED | 催办补录后重导；确认剔除 `INCLUDED` |
| DISQUALIFIED | 取消考试资格 | 等同缺考 | `INCLUDED` 确认 |
| SUSPENDED | 休学/无学籍 | 整生排除 | 需纳入时 `INCLUDED` |
| NON_NUMERIC_SCORE | 等级制成绩 | 「优=95/良=85/中=75/及格=65」已前置映射，此队列仅剩罕见文本 | `INCLUDED` 或人工换算 |

> ⚠️ 进入 CALCULATED 的门禁：MISSING/DEFERRED_EMPTY/DISQUALIFIED/NON_NUMERIC_SCORE 必须全部裁决（`INCLUDED`=按系统默认规则处理确认）。

裁决查看多行明细：`GET /grades/issues/:id/lines`（返回该生该课全部行，含补考行）。

### A4. 授权班委（每班一名）

```
PATCH /users/:userId            { role: "CLASS_LEADER" }
POST  /students/classes/:id/leader   { studentNo }        # 绑定为班级负责人（数据范围=本班）
```

### A5. 材料收集与两级审核

批次流转 `COLLECTING` 后学生可提交。审核工作台：

```
GET  /applications?batchId=&status=SUBMITTED          班委看本班待初审（服务端强制）
GET  /packages?batchId=&status=SUBMITTED              材料包列表（zipFileId 可在线浏览）
POST /reviews/first        { ids, action:"PASS"|"REJECT", comment? }   班委初审
POST /reviews/second       { ids, action:"APPROVE"|"REJECT", grantedScores?: {id: number}, comment? }
```

复审核定分值：默认取学生申报分，可用 `grantedScores` 逐条覆盖（超上限自动截断并记录）。全部操作留 ReviewLog 轨迹并通知学生。

### A6. 计算

```
POST /calc/run   { batchId, dryRun: true }   试算：不落版，返回逐生 diff（NEW/CHANGED/REMOVED）+ flag 汇总
POST /calc/run   { batchId }                 正式：生成新版本 CANDIDATE（旧候选版作废）
GET  /calc/results?batchId=&version=&classId=&page=     结果预览（含 breakdown 每分项来源）
GET  /calc/results/:studentId?batchId=&version=          单生可解释明细
```

> golden 验证口径：用 `大数据2025级1班.xlsx` 模板 P 列回算 30/30 一致（见 `test/golden-from-files.spec.ts`）。

### A7. 发布、公示、异议、更正

```
POST /publish/release        { batchId, publicityDays: 3 }   → 物化 Redis 快照 + 建公示轮次 + 全员公告；批次自动转 PUBLICITY
GET  /publish/rounds?batchId=
GET  /publish/objections?batchId=                            异议看板
POST /publish/objections/:id/handle   { status:"ACCEPTED"|"REJECTED", note }
```

异议成立后的更正闭环：
1. 裁决/更正数据（如补考行 MANUAL_PICKED）
2. `POST /calc/run`（公示期允许，生成 CANDIDATE 新版）
3. `POST /publish/incremental { batchId }` → 自动检测分数变化学生，晋升其 PUBLISHED 版本并精准刷新快照（返回 `{refreshed, students}`）

二次公示 = 再次 `release`（round+1，全员重写快照）。

### A8. 导出（严格 30 列模板）

```
POST /exports   { batchId, scope:"CLASS", classId }  → { jobId }   分班单 sheet
POST /exports   { batchId, scope:"GRADE" }                            全年级 29 班
GET  /exports/history?batchId=                 summary 含 fileUuid/fileName
GET  /files/:uuid/download                     下载 xlsx（xlsx 经审计 EXPORT_RESULT）
```

发布态导出取每生最新 PUBLISHED 行（含增量更正学生）；未发布批次导出当前候选版（试算预览）。

### A9. 看板 / 审计 / 公告

```
GET  /stats/overview?batchId=     学生/提交率/审核积压/异常计数/分数分布/Top10
GET  /users/audit-logs?action=    审计（LOGIN/IMPORT/GRADE_RESOLVE/FIRST_REVIEW_PASS/SECOND_REVIEW_APPROVE/PUBLISH/PUBLISH_INCREMENTAL/OBJECTION_HANDLE/EXPORT_RESULT/RULE_UPDATE…）
POST /announcements               { title, content, pinned? }
```

## B. 班级负责人（班委）

账号=学号（被管理员提权 CLASS_LEADER 并绑定班级后，数据范围锁定本班）。

1. **初审**：`GET /applications?batchId=&status=SUBMITTED` 只会返回本班申请；逐条查看材料（附件在线预览 `GET /files/:uuid/download`；材料包 `GET /files/:zipFileId/zip/entries` 看目录树、`GET /files/:zipFileId/zip/preview?path=社会实践.pdf` 在线预览包内 PDF/图片）→ `POST /reviews/first {ids, action, comment}`（退回必须写原因，学生可见可重提）
2. **材料包初审**：`POST /reviews/packages/first {ids, action}`——核对后端规范命名报告（namingReport）与包内清单
3. 复审由辅导员完成；初审/复审结果都会进学生通知

---

## C. 学生

账号=学号，初始密码=学号后 6 位，首登强制改密（未改密前仅能调改密接口）。

### C1. 加分申请（收集期内）

```
GET  /rules/items                            规则字典（detailSchema 驱动动态表单）
POST /files/upload?kind=EVIDENCE             上传佐证（pdf/jpg/png…，白名单+魔数校验）
POST /applications                           { batchId, ruleItemId, title, detail, fileIds }  → 自动：表单校验、白名单命中、申报分值、同项去重
GET  /applications/mine?batchId=             我的申请 + 审核轨迹时间轴
POST /applications/:id/withdraw              撤回（仅 SUBMITTED/被退回状态）
```

### C2. 材料包（两板块，后端规范打包）

```
POST /packages/submit    { batchId, section:"PRACTICE_VOLUNTEER"|"BONUS_EVIDENCE", items:[{fileId, role}], meta? }
```

后端按命名规范生成 zip 并留档（命名报告含每份文件的规范名）：
- 板块一：文件名「社会实践」「志愿服务」，zip `学号 姓名 N社会实践 N志愿服务`
- 板块二：文件名「活动/比赛全称」（国/省/市/校前缀），zip `学号 姓名 N加分证明 N比赛活动 证书名 干部名称`

### C3. 查分与异议

```
GET  /publish/scores/mine          发布后可查（快照直读，明细含三维小分/排名/每分项）
POST /publish/objections           { batchId, content }    仅公示期内；同轮重复提交被拦（409）
GET  /publish/objections/mine      处理结果
```

异议受理后：管理员更正 → 重算 → 增量发布，成绩自动更新，无需重新查询操作。

### C4. 通知与公告

`GET /notifications/mine`（初审/复审/异议处理/发布全员公告自动送达）· `GET /announcements`。
